# 패스오더 · 점주 QR 페이지

편지 속 QR을 찍은 사장님이 보는 페이지. 손님들의 요청 → 지금 앱 화면 → 시작하면 달라지는 것 → 마무리 → 전화 안내 신청(번호 · 통화 시간대). 정적 파일만으로 동작하며 GitHub Pages에 그대로 올립니다.

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 · 전화 안내 신청 시트 · 접수 완료 화면 (한 파일) |
| `config.js` | 기록 전송 주소 · 통화 안내 일수 |
| `assets/img/` | 손님 아바타 5장 · 가게 그림 · 화살표 · 선물 등 |
| `apps-script/Code.gs` | 구글 시트 「QR 접속」 「문의」 탭에 기록을 쌓고 슬랙에 알리는 코드 |
| `.nojekyll` | GitHub Pages가 파일을 그대로 서빙하도록 하는 빈 파일 |

## 링크 (편지마다 다른 QR)

편지 한 통마다 QR에 아래 주소를 넣습니다. **편지코드 `c` = 「신청」 · 「편지」 탭의 신청번호**입니다. 시트 「편지」 탭의 「점주 QR 링크」 열에 편지마다 자동으로 만들어져 있습니다.

```
https://<계정>.github.io/<저장소>/점주QR/?c=신청번호
```

매장명 · 편지를 전한 손님 닉네임 · 문의 기한(도착일 + 21일)은 편지코드로 시트에서 받아 옵니다. 손님 열쇠(`t`)는 QR에 넣지 않습니다(사장님이 손님 대신 기록할 수 있게 되므로). 편지코드가 없으면 예시 값으로 보이고 기록도 남지 않습니다(화면 확인용).

## 숫자

링크에 `v` `r` `e`가 없으면 편지 코드로 고정된 난수를 씁니다(같은 편지는 늘 같은 숫자). 범위는 `index.html`의 `RANGE` 한 줄에 있습니다.

| 항목 | 범위 | 근거 |
|---|---|---|
| 찾아본 손님 `v` | 90~220명 | 대상 매장 697곳 실측 중앙값 198명(10/12) |
| 요청한 손님 `r` | 5~14명 | 앱 도입 요청 매장당 중앙값 12건 |
| 다른 가게 주문 `e` | `v`의 25~40% | 찾아본 수에 비례 |

요청 손님 카드는 4명까지 + 「N명 더」. 이름은 가림 풀 12개, 날짜는 최근 90일, 한마디는 앱 「도입 요청」의 이유 4가지 안에서만 고릅니다. 편지 손님 한마디 날짜는 최근 3~30일.

## 기록을 구글 시트로 받기

모집 · 내 편지와 같은 시트 · 같은 웹 앱(`../모집랜딩_배포용/apps-script/Code.gs`)을 씁니다.

- 「QR 접속」 탭: 접속시각 · 편지코드 · 열쇠 · 매장ID · 매장 · 손님 전달 기록 있음 · 기기 · 열린 앱 · 유입 URL (열 때마다 1줄) + 「모집대상」 QR 접속 Y
- 「문의」 탭: 접수시각 · 편지코드 · 열쇠 · 매장ID · 매장 · 손님 닉네임 · 전화번호 · 통화 시간대 · **매장 첫 문의**(같은 매장의 첫 접수면 Y, 10,000원 쿠폰 귀속 후보) · 기기 · 유입 URL + 담당자 입력(처리상태 · 첫 통화일 · 결과 · 성공쿠폰 지급일 · 메모) + 「모집대상」 사장님 문의 Y
- 슬랙 알림은 채널이 정해지면 붙입니다(외부 호출 권한 승인이 한 번 더 필요).

## 올리기 전에 채워야 할 값 (`config.js`)

`SUBMIT_URL`은 모집 · 내 편지와 같은 웹 앱 주소가 들어가 있습니다. `CALL_DAYS`는 접수 화면의 「○○ 안에 담당자가 전화드려요」입니다.
