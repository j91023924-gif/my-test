# 패스오더 · 점주 QR 페이지

편지 속 QR을 찍은 사장님이 보는 페이지. 손님들의 요청 → 지금 앱 화면 → 시작하면 달라지는 것 → 마무리 → 전화 안내 신청(번호 · 통화 시간대). 정적 파일만으로 동작하며 GitHub Pages에 그대로 올립니다.

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 · 전화 안내 신청 시트 · 접수 완료 화면 (한 파일) |
| `config.js` | 기록 전송 주소 · 통화 안내 일수 |
| `assets/img/` | 손님 아바타 5장 · 가게 그림 · 화살표 · 선물 등 |
| `apps-script/Code.gs` | 구글 시트 「QR 접속」 「문의」 탭에 기록을 쌓고 슬랙에 알리는 코드 |
| `.nojekyll` | GitHub Pages가 파일을 그대로 서빙하도록 하는 빈 파일 |

## 링크 (편지마다 다른 QR)

편지 한 통마다 QR에 아래 주소를 넣습니다. 편지 코드 `c`가 열쇠예요 — 어느 손님의 편지로 문의가 들어왔는지(10,000원 쿠폰 귀속)와 숫자 고정에 씁니다.

```
https://<계정>.github.io/<저장소>/owner/?c=L-0001&store=매장명&nick=닉네임&due=2026-11-26
```

| 파라미터 | 쓰임 | 없으면 |
|---|---|---|
| `c` | 편지 코드. 시트 기록의 열쇠, 숫자 난수의 씨앗 | `L-0001` |
| `store` | 화면의 매장 이름 | 패스카페 |
| `nick` | 편지를 전한 손님의 앱 닉네임 | 라떼좋아 |
| `due` | 사장님 문의 기한(YYYY-MM-DD). 「○월 ○일까지」 | 오늘 + 21일 |
| `v` `r` `e` | 찾아본 손님 · 요청한 손님 · 다른 가게 주문 수. 실제 값이 있으면 넣음 | 아래 범위 안 난수 |
| `seed` | 난수 씨앗을 따로 주고 싶을 때 | `c` 값 |

## 숫자

링크에 `v` `r` `e`가 없으면 편지 코드로 고정된 난수를 씁니다(같은 편지는 늘 같은 숫자). 범위는 `index.html`의 `RANGE` 한 줄에 있습니다.

| 항목 | 범위 | 근거 |
|---|---|---|
| 찾아본 손님 `v` | 90~220명 | 대상 매장 697곳 실측 중앙값 198명(10/12) |
| 요청한 손님 `r` | 5~14명 | 앱 도입 요청 매장당 중앙값 12건 |
| 다른 가게 주문 `e` | `v`의 25~40% | 찾아본 수에 비례 |

요청 손님 카드는 4명까지 + 「N명 더」. 이름은 가림 풀 12개, 날짜는 최근 90일, 한마디는 앱 「도입 요청」의 이유 4가지 안에서만 고릅니다. 편지 손님 한마디 날짜는 최근 3~30일.

## 기록을 구글 시트로 받기

모집 · 내 편지와 같은 스프레드시트 · 같은 웹 앱을 쓰는 것을 권합니다. 기존 `Code.gs`의 `doPost` 첫 줄에

```
if (d.type === 'scan')    return recordScan(d);
if (d.type === 'inquiry') return recordInquiry(d);
```

를 넣고 이 폴더의 `recordScan` · `recordInquiry` · `sheet_` 함수와 `SLACK_WEBHOOK` 변수를 붙여 넣은 뒤 다시 배포하면, 같은 웹 앱 URL을 `config.js`의 `SUBMIT_URL`에 넣으면 됩니다.

- 「QR 접속」 탭: 접속시각 · 편지 코드 · 매장 · 유입 URL (페이지를 열 때마다 1줄)
- 「문의」 탭: 접수시각 · 편지 코드 · 매장 · 닉네임 · 전화번호 · 통화 시간대 · 유입 URL · 처리상태 · 첫 통화일 · 결과 · 쿠폰 지급일 (뒤 네 칸은 담당자가 채움)
- 슬랙 알림에는 매장 · 시간대 · 편지 코드만 들어가고 번호는 시트에만 남습니다. `SLACK_WEBHOOK`을 비우면 알림 없음

## 올리기 전에 채워야 할 값 (`config.js`)

`SUBMIT_URL`만 비어 있습니다. 모집 랜딩 `config.js`와 같은 웹 앱 주소를 넣으세요.
